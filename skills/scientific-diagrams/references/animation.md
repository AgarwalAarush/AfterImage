# Animation mode for scientific diagrams

Read the parent scientific-diagrams skill first. Animation is an extra dimension of the same scene, not a second scientific/design pipeline. Keep its source, geometry, typography, and review rules.

## Show changes, preserve identity

Write a beat's input, operation, visible change, and output. Results appear after their dependencies. Preserve context and identity through copies, substitutions, branches, and accumulation. Draw what changes: reusable state arriving at the next input, selected entries becoming assigned, an accumulator updating, or an accepted prefix surviving verification. Pulses and traveling dots alone do not demonstrate those operations.

Do not falsely serialize parallel computation. Label attention-guidance sequences and illustrative pacing; durations never represent measured latency without evidence. Separate training and inference. Proposals remain candidates until verification. Unknown/unavailable never turns into a zero/empty value. Keep labels still while scientific objects move. Reserve label space outside moving objects' full swept bounds. Prefer discrete swaps over overlapping mathematical text or headings.

One deterministic timeline must generate live animation, static sampled frames, and poster. Stable semantic IDs connect the storyboard to visible groups. Choose the smallest suitable tool: SVG/SMIL or CSS for a finite standalone sequence; component state/WAAPI when interaction requires it. Do not add a motion dependency for highlights. Preserve identities instead of regenerating the whole picture per beat.

## Quiet playback

For embedded worked examples autoplay while visible, with one unobtrusive Play/Pause button. Preserve an explicit pause across offscreen/hidden states. Pause on page hide and offscreen; resume the same time. Use a final hold and short clear fade/reset, never reverse algorithm steps to loop. Reduced motion defaults to the complete static poster and responds to preference changes; explicit Play can opt into motion. Print uses the poster.

Use the page's appearance setting, without a figure theme toggle. Keep review time/theme controls on an author-only surface. One useful caption and accessible description suffice; omit stage badges, counters, repeated definitions, legends, and source banners unless essential. The figure's scientific state should communicate progress.

## Additional acceptance

Apply [the review loop](review-loop.md) to every beat and transition midpoint, including first/last frame and reset. Check continuity, liveness, truthful availability, candidate/accepted distinction, result ordering, swept collisions, and semantic state changes. Browser verification covers autoplay, pause/resume without resetting, loop hold/reset, narrow desktop type, inherited themes, reduced-motion poster, print, and offscreen/page-hide behavior. Record observed versus code-inspected coverage. Never approve only the final still.

See [the storyboard contract](storyboards-and-review.md). EAGLE's state-reuse motif is an example, not a template for every mechanism.
