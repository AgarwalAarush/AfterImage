# Targeted reading-kit repairs

Implemented locally; not deployed. This follows the [production failure audit](repair-system-audit-2026-10-01.md). The audit describes the previous worker, including the two MegaBlocks failures; this document describes the replacement behavior.

## Controller and model contract

`worker/repair-controller.ts` owns candidate adoption and the repair budget. `worker/repair-model.ts` owns the model-facing defect, verification, and native patch schemas. Opening notecards and study supplements share this controller.

A reviewer identifies a defect's owner (content, representation, renderer, schema, execution), evidence, acceptance condition, known source IDs, and exact JSON-pointer targets. The catalog is derived from the actual Zod generation schema, including source enums and length/array bounds. Duplicate findings within one review consolidate their acceptance conditions and count once. Before a representation replan, a bounded feasibility assessment checks whether existing native fields can satisfy the entire finding; it cannot waive acceptance conditions, source requirements, or the preflighted assignment contract. Ordinary edits cannot replace the whole recall, scene, supplement, figure list, or quiz. An owning array may be targeted for a real structural change; it supersedes child targets. Patches carry the candidate fingerprint and each target's preimage hash. Unknown keys, stale inputs, overlaps, out-of-bounds values, and no-op patches are rejected before adoption. Unaffected data remains unchanged.

Every open defect enters a private ledger. Subsequent review must explicitly verify it against the current candidate and evidence. Omission leaves it disputed; recurrence reopens it. Prior positive reviews do not freeze an incorrect equation. Final acceptance requires a complete fresh review and no unresolved ledger entries. Candidate/review records bind to source content, generation schema, renderer sources, fonts, rubric, and pipeline version. Those records are private artifacts, not new `Paper` fields or browser statuses.

Notecards retain four repair attempts; supplements retain two. Each rejected patch and representation fallback consumes an attempt. One explicit representation replan is available within that budget, including any planning fallback. A notecard replan may replace the scene and explicitly implicated recall fields; a supplement replan replaces only identified figures. Replacement plans are adopted only after their patch validates. Renderer findings identify the affected scene/figure even when there is no editable field, so supplement fallback can locate exactly one artifact. Execution interruptions stop separately and cannot become content-edit retries. Existing bounded capacity retries remain; this change does not replay uncertain API/storage writes.

Received model output may have an exact JSON Markdown fence removed. Missing scientific content or malformed JSON is never inferred. Private step records report elapsed time, schema/output fingerprints and failure ownership. Initial planning/drafting failures also receive a private report.

## Planning and review

`worker/capabilities.ts` supplies the authoritative scene JSON schema and renderer semantics to planning, generation, technical/visual review and repairs. Allocation/routing plans require a concrete bounded illustrative example. Preflight checks identifiers, assignments, arithmetic and native panel invariants before drafting. Shared identities are individual transferred items; padding is implicit capacity, not fake token identities. Draft allocation/routing comparisons must preserve the preflighted panels and memberships or explicitly replan.

Deterministically safe candidates receive both technical and rendered visual review before editing, even when technical checks fail. Malformed/unsafe scenes are localized before rendering. Technical review also audits every equation's current fingerprint, symbol definitions, dimensions/cardinality, source evidence and source-versus-derived origin. Each derived equation needs its own disclosure. Open visual defects are independently verified with the same current rendered images, not encoded data alone. These remain model judgments supported by source data, not a formal proof of scientific correctness.

Supplement review checks every figure, every question, the correct answer and distractor explanations. Quiz repairs must name dependent options, indices and explanations when needed. Quiz arrangement runs once; repair does not reshuffle unrelated questions.

## Allocation renderer

Optional `blockSize` (integer 2–6, or absent/null) groups illustrative slots into renderer-drawn outlines with visible block gaps. It requires illustrative disclosure and capacities divisible by the declared size. One expert remains one allocation group; padding and occupancy derive from capacity and item identities. Physical implementation dimensions belong in cited captions, not illustrative geometry. Legacy panels without the field retain identical SVG output. Desktop is the release acceptance target; the existing narrow-view gate remains.

Schematic token geometry now separates token circles at narrow widths and extends token/module/bank connectors to visible shapes. Token/bank identity limits already enforced by validation now also appear in the native schema (four characters); longer names remain in labels and captions. The dependency-layer bounds are included in the capability notes. Memory-transfer numbers now include dotted annotation leaders to their exact connector source ports, including when crowded routes force numbers into the margin. Leaders are annotations, not additional scientific transfers. These corrections were found during nonpublishing TriRoute/MegaBlocks/FlashAttention evaluations; no new rendering primitive or mobile product flow was added.

Reported-value validation now recognizes strictly grouped thousands such as `5,048` as the exact number `5048`, without treating the group fragments as separate evidence or merging malformed/list separators. Both study and opening-illustration numeric gates share this parser. Source support, units/context review, and illustrative disclosure remain required; values are never changed to bypass the validator.

## Local verification and release

The full suite passes 140 tests, including 25 controller/model-contract regressions: complete short-unit edits, scope/citation preservation, native bounds and source enums, stale/no-op patches, unresolved/omitted defects, bounded fallback, rejected-plan adoption, supplement preservation, execution ownership, review bindings, eight-token/six-token preflight, block arithmetic, SVG collisions and legacy rendering. Typecheck and the production build pass. Native lanes and diagonal block fixtures were rendered and visually inspected at desktop and narrow widths.

Nonpublishing model evaluations and failure replays used MegaBlocks, TriRoute, QLoRA and FlashAttention. They were iterated during implementation, not run as a frozen acceptance-rate benchmark. Opening and supplement outcomes are reported separately. One malformed local replay wrapper was rejected at the schema boundary and excluded from paper-quality outcomes. Replays use prior generated candidates and fresh source/rendered reviews; they do not publish or mutate library jobs. Raw artifacts stay ignored under `.artifacts/`.

All inspected adopted patch/replan traces changed zero leaf fields outside their authorized targets. An adopted artifact replan records its before/after fingerprints and plot kinds on affected renderer/representation ledger entries. Verification explicitly distinguishes same-representation correction from replacement proof; replacement resolution is rejected without that receipt or for scientific content findings. A representation replan can change the entire explicitly identified scene/figure; this metric does not claim that such changes are small or scientifically correct. First-pass opening acceptance was zero in these selected problem cases; corrected QLoRA supplement acceptance was first-pass. Private records retain model calls, elapsed time, candidate snapshots, recurring/resolved entries and failure owners. For example, the MegaBlocks supplement replay used four model calls totaling about 53 seconds, while the unchanged QLoRA supplement used one call totaling about 14 seconds; source retrieval and previously generated drafts are excluded from those model-time totals. These are diagnostic timings, not comparative performance claims.

TriRoute's remaining finding concerned a uniform positive expert cost applied to a selection containing the null expert. A later inspection of the complete paper found the needed clarification in Appendix C: the reference implementation excludes index 0 without renormalizing the remaining selected weights. The previous source bundle omitted all appendices and code listings even though it was marked full-text. The [evidence-aware follow-up](evidence-aware-repairs-2026-10-01.md) addresses that extraction defect and evidence/review orchestration; the table above remains the earlier evaluation cohort, not the follow-up's results.

Manual source spot checks confirmed MegaBlocks' token-versus-assignment distinction, local-padding arithmetic and SDD/DSD order, and exposed the TriRoute cost interpretation issue and the QLoRA grouped-numeral false rejection. Rendered fixtures/rejected candidates were also inspected for block grouping, overlapping circles, source attachment and memory-label association. This is limited adjudication, not an independently measured false-approval rate. Model reviews can still miss scientific details; more acceptance alone is not evidence of accuracy.

Release the compatible web/API schema and renderer first. Then verify the worker queue, let active jobs finish, and switch workers to this version. Preserve review/publication gates. Stored failed kits do not regenerate automatically, and this local implementation has not changed MegaBlocks or TriRoute in the production library. An explicit preparation/retry after the compatible release uses the updated worker.
