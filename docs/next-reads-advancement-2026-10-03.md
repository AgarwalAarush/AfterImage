# Next reads advances after a choice

Next reads is a discovery shortlist of papers outside the Library. Previously `saved` entries were still eligible, and save/preparation/dismissal did not automatically request replacements. As a result a prepared paper stayed on the home shortlist and its bookmark became an inert checkmark.

Saving, preparing, importing, marking as Reading/Read, or choosing Save for later removes any corresponding shortlist entries in the same confirmed state write. Preparation still saves the paper and queues the existing generation flow. The direct dismiss control records `irrelevant` feedback, removes the recommendation, and requests another without saving the dismissed paper. Already know it also excludes the paper and advances the shortlist. Useful and Too advanced remain inputs to future ranking. Dismissal influences future research-fit assessments as negative feedback; it is not a blanket exclusion of a topic.

Automatic replacements use a recommendation job with private `recommendationMode: "refill"`. Publication retains the remaining eligible recommendations and fills only vacant slots, up to three. Explicit Refresh suggestions continues to replace the whole shortlist. An active queued job absorbs repeated actions; a running job records a private refill request and rechecks live exclusions when publishing. Newly saved or dismissed papers are filtered instead of failing the entire result. If these late actions leave vacancies, publication queues one follow-up. Fewer suitable candidates can produce a smaller shortlist without a repeated discovery loop. A nonempty direction, one active recommendation job, and the existing shared limit of twelve jobs per hour remain enforced. When the limit prevents a refill, removal still succeeds and the reader can refresh after capacity returns.

Recommendation jobs run before queued long-form generation, so a new discovery list need not wait behind a queued kit. Running jobs are not interrupted. Preparation queue positions use this same priority. Home shows a replacement message only when a recommendation job is actually queued/running; an idle empty list offers refresh or reading direction. Existing stored saved recommendations are filtered from browser state and exports without migrating the stored library or fabricating a queue write. Browser polling only reads state; it does not run discovery. Recommendation claims use a three-minute lease renewed by the existing minute heartbeat. A stopped worker therefore releases an orphaned refill sooner, while a healthy longer discovery run remains protected. Generation and study retain fifteen-minute leases; every job retains the existing three-attempt bound and lease-token checks. This recovery refinement is API-only and does not require a worker restart.

## Popularity and relevance

For each relevance search, OpenAlex contributes both relevance-sorted and citation-sorted results. Recent OpenAlex searches retain their two-year window; arXiv recent searches sort by submission date. The sources are interleaved and deduplicated before bounded canonical arXiv resolution. Citation metadata attaches only to a work with one unambiguous canonical arXiv identity. Invalid/missing counts remain unknown.

The model assesses up to twelve verified candidates for research relevance, next-step usefulness, and main/adjacent thread. A deterministic rank admits candidates only at relevance >= 0.6 and computes `0.70 * relevance + 0.10 * nextStep + 0.20 * popularity`. Popularity uses `min(1, log10(1 + cited_by_count) / 4)` to bound the advantage of extremely cited papers. When OpenAlex supplies a valid citation-normalized percentile in [0,1], popularity blends 60% log citations and 40% normalized percentile; otherwise it uses the count alone. Unknown index coverage receives a neutral 0.5 rather than a fabricated zero. A strong adjacent candidate (relevance >= 0.75) and a particularly relevant recent candidate (>= 0.85) retain a place when available, protecting exploration and new work from cumulative citation counts.

Citation counts are a proxy for research influence, not evidence of correctness. The metadata and assessment scores stay in the worker; published recommendation and Paper schemas are unchanged. OpenAlex's [work attributes](https://help.openalex.org/data/works/attributes/) and [sort documentation](https://help.openalex.org/api/sorting/) specify the fields and retrieval order.
