# Documents

The Documents tab is a private reading shelf for owner-uploaded Markdown (`.md`, `.markdown`) and PDF (`.pdf`) files. It is separate from the arXiv paper library. Uploads are limited to 4 MB per file, checked by extension and content, and deduplicated by SHA-256. Markdown is decoded as UTF-8. PDF files must have a PDF header. Uploads do not enter the recommendation or worker pipeline.

`GET /api/documents` returns metadata only. The authenticated `GET /api/documents/:id` loads one Markdown body or serves one PDF. `?meta=1` returns metadata for the reader, and `?download=1` downloads the original file. `POST /api/documents` accepts one multipart `file`; `DELETE /api/documents/:id` removes it. Writes require same-origin requests. All routes require the existing owner session and use private, no-store responses.

Local development stores document bytes in the `documents` table of `.data/afterimage.sqlite`, outside the large `afterimage_state` JSON. The hybrid production release uses the same table in the authoritative macserver SQLite file. Vercel's authenticated routes call five allowlisted actions on the existing signed storage bridge; the bridge creates the table on startup and runs under the restricted `_afterimage` service account. Document uploads, downloads, listing, and deletion never use the stale Supabase state. The optional explicit `AFTERIMAGE_STORAGE=supabase` mode uses the service-only `afterimage_documents` table from `supabase/migrations/202609280001_documents.sql`, but is not the selected production path. A Vercel deployment without a configured bridge rejects document operations.

Before enabling the new Vercel routes, back up the current macserver database, install the compatible storage bridge code, restart the isolated bridge, and verify its signed document actions. After the table is created, verify that a new local snapshot and restore include the `documents` table. The 4 MB file limit yields an encoded body under the bridge's 8 MB request cap. The attached reference guides can be uploaded through the UI; attachments are not bundled into the public build.

For the isolated service, stage `scripts/storage-server.ts`, `src/lib/documents.ts`, `src/lib/macserver-client.ts`, and `scripts/install-documents-storage-macserver.sh` in a private directory on macserver. Run the installer there as administrator, passing the absolute staging directory. It checks the host and service paths, creates a private pre-update snapshot, installs only the three code files, restarts the bridge, tests signed list/status calls, then backs up and restores the new table locally. If a post-install check fails, it restores the previous code and restarts the bridge. It never copies database content off macserver. Publish the Vercel routes only after that check passes.

The Markdown reader supports GitHub-style tables and lists, fenced code, inline/display math (both dollar and LaTeX bracket delimiters), and the citation anchors used in the supplied Deep Research exports. Raw HTML passes through an allowlist sanitizer before KaTeX rendering. The PDF reader displays the private PDF route in a same-origin frame and offers original-file download. That route alone overrides the app's `X-Frame-Options: DENY` with `SAMEORIGIN`. Neither format is sent to the worker or a model automatically.
