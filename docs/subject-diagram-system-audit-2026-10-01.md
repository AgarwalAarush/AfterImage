# Why the Subjects diagram pipeline admitted a poor layout

The Whisper screenshot exposed a system defect: a scientifically valid, unclipped scene could still separate a symbol from its owning text, align neighboring text inconsistently, and reserve unnecessary empty space. Correcting one card did not close that failure mode.

## Evidence and diagnosis

| Before | After | Why |
| --- | --- | --- |
| The source critic received semantic JSON; its passing result was easy to confuse with visual acceptance. | Source review explicitly audits scientific ownership and declines to certify layout. Rendered acceptance remains separate. | A source-correct symbol can still be visually detached from its owner. |
| Deterministic validation mainly checked references, available states, fit, and overlap. | Every storyboard state also checks text axes, symbol association, content occupancy, row centers, endpoint attachment, and avoidable arrow detours. | Bounds are necessary, but do not establish a coherent visual relationship. |
| Layout estimated text widths by character count. | Product-font metrics drive text sizing, with actual browser font/box checks before approval. | The real font left a 40.7px encoder-to-symbol gap where estimated geometry claimed a nearby identity. |
| A visual report needed four arbitrary view descriptions. Duplicate descriptions and endpoint-only screenshots could pass. | The report covers every beat and adjacent transition at both desktop widths and both themes, with hashed, decoded PNG evidence and explicit grouping/spacing findings. | A string saying a view was checked is not evidence of coverage. |
| Fingerprints covered scene and renderer, but omitted inherited reader styles and fonts. | Approval also binds presentation styles, theme, typography, actual font assets, and review policy. | A font or host CSS change can invalidate an otherwise unchanged SVG. |
| A successful build could silently ship withheld walkthroughs. | The publication audit runs before builds and rejects any shipped sidecar lacking current complete approval. | Hiding an invalid scene is safe at runtime; it must also be visible as a release failure. |
| Inventory checks enumerated only files that happened to exist. | The audit requires every lesson and separately declared mechanism ID, rejecting missing files, duplicates, unknown IDs, and orphan sidecars. | Deleting a publication must not turn an incomplete release into a passing audit. |
| The lesson loader validated public fields but returned the raw object. | The loader returns a validated, allowlisted publication projection, including bounded source and review metadata. | Accidentally added private excerpts or review diagnostics must not reach client serialization. |

Deployment uses the pinned lockfile install and tested webpack build. | Upload filtering and runtime bundle filtering are separate release boundaries; build-input drift must fail closed. |

The old visual branch accepted `checkedViews: string[]` with a minimum length of four, without uniqueness, actual width/theme semantics, image validation, or beat coverage. Existing content/renderer hashes protected the reviewed bytes but did not prove that anyone had reviewed the relevant states. Prior author checks also selected upper initial states and lower final states, leaving intermediate grouping changes unexamined. These were process and gate failures, not evidence that the scientific source invented the encoder's input.

The new semantic ownership checks reject unused identities, unexercised relationships, ambiguous aliases, disconnected dependency islands, and empty symbolic containers. All fourteen existing scenes already satisfy these checks. This is preventive tightening, not the explanation for the corner-token defect.

## Enforced publication path

Generation provides bounded semantic objects and symbolic identities. It cannot provide arbitrary SVG, CSS, or coordinates. Host semantic and every-state geometry checks run before source review and again at publication/runtime. Source review has a distinct ownership result; cached hashes do not bypass current policy checks.

Visual acceptance uses a versioned report with a separate independent reviewer, typed observations, exact parent/scene/renderer/presentation fingerprints, all four desktop views, every beat, and every adjacent transition. Approval validates the actual PNG bytes, dimensions, bounded private paths, and distinct state captures. Published sidecars retain compact proof hashes and coverage counts; screenshots and private review observations remain outside public artifacts.

Current walkthroughs change status colors and connector opacity over 180ms while keeping object geometry fixed. Their transition review compares the adjacent actual browser states and verifies that no spatial motion is claimed. A future spatial transition requires real intermediate evidence; endpoint-only evidence cannot certify a moving object's swept area.

`scripts/subject-mechanism-browser-audit.js` complements deterministic envelopes with actual browser text rectangles, shared inline axes, label-to-symbol distance, complete glyph containment, text collisions, and the introduction-to-diagram gap. It is a read-only measurement tool, not an aesthetic approval function. An independent visual critic must still inspect the rendered evidence and report defects or concrete observations.

Text metrics are generated from the checked-in Overused Grotesk Roman 400 font, with both its digest and the public variable-font digest recorded. Encoder title/detail measurements differ from browser variable-400 measurements by less than 0.11px; the regression tolerance is 0.25px. This is an explicitly tested near-match, not a claim that the fonts are byte-identical. Supported glyph advances and pair kerning drive wrapping and layout without a browser font-parser dependency. Unsupported glyphs reserve conservative width and disable inline badge positioning; their separate centered glyph rows still require actual browser review. Production build preflight verifies the public font digest. A changed font requires metric regeneration and fresh visual acceptance.

`scripts/prepare-subject-visual-review.ts --run` resets presentation approval only when the exact previously reviewed semantic and parent digests remain unchanged. Any changed scientific scene or parent must return through source review. `npm run subjects:verify` and the build preflight detect withheld content instead of accepting a build with missing walkthroughs.

For a repeatable capture, the browser reviewer selects each actual beat through its normal controls at each required desktop width/theme, runs the read-only DOM audit, and saves a full-page screenshot plus the mechanism section's measured bounds and capture-time bindings. `scripts/process-subject-review-captures.ts` crops review regions from those browser pixels, hashes them, binds DOM facts to each actual beat, and writes the private frame index. A critic must confirm that the complete diagram, current explanation, and step controls are actually visible; a crop cannot prove a title or Play state that it omits. It creates no SVG or synthetic screenshot and emits no passing visual judgment. A separate critic supplies the required observations before the normal `--approve-visual` command can publish a sidecar.

The fresh review caught four ResNet captures labeled Light that actually showed Dark. The gate and independent critic rejected the duplicate-theme set. Replacement captures verify the resolved DOM theme and selected state before and after each native screenshot; only those replacement pixels received approval. View names alone remain insufficient evidence. Isolated publication tests also remove a lesson and a mechanism file and inject private fields at several nesting levels; the audit detects both deletions and the reader projection strips all injected private fields without changing public content.

The critic also rejected a YOLO full-page capture containing a stale enlarged offscreen panel, despite correct DOM bounds. Direct viewport inspection showed the normal diagram; bringing the walkthrough into view before a new native capture removed the capture artifact. The failed pixels remain private evidence, and the replacement must pass independent inspection. Capture automation therefore selects the first beat to establish a hydrated interactive page, clicks the desired appearance, verifies the actual resolved theme, and brings the walkthrough heading into view before capture. It verifies selected identities again after capture and stops on a mismatch. Neither a DOM-only pass nor a filename establishes valid visual evidence.

NeRF's narrow captures exposed a second capture-system failure: a native full-page snapshot changed the scrollbar gutter, reflowing the document after its crop was measured. The critic rejected ten incomplete header captures. The committed `scripts/capture-subject-mechanism-browser.js` establishes native snapshot geometry before measuring the card and requires unchanged crop, canvas, viewport, object geometry, theme, and selected identities across the final capture. Required header, playback, diagram, explanation, and step regions must fit the measured card. A regression test rejects gutter reflow, crop drift, missing regions, and changed states. Replacement NeRF captures use this helper; it produces no passing judgment and cannot bypass independent pixel inspection.

The release trace check rejected 5,620 private review files on two routes and a local SQLite file on six API routes. Existing upload exclusions prevented their remote transmission. Global Next tracing exclusions remove those entries even for locally prebuilt deployments; the fresh whole-build audit scans all 21 traces. A future code split can isolate offline verification imports, but the explicit private-file exclusion remains required. Prebuild failures emit only bounded public-source fingerprints and error classes, making common deployment-binding failures diagnosable without printing private review or environment content.

## Boundaries and acceptance

Subjects sidecars use their own semantic renderer and approval path. The paper worker already has separate rendered SVG/font-outline inspection and image critique; its checks never ran on Subjects. Its layout vocabulary differs, so applying the entire Subjects inspector to stored paper scenes would be incorrect. Shared containment, ownership, occupancy, and endpoint principles should use renderer-specific adapters in any future worker release. Historical paper geometry and the running worker remain unchanged in this web release.

The regression fixture reproduces the old centered-title/left-detail/corner-symbol composition. It has no clipping or collision, yet now fails the grouping contract. Other adverse fixtures cover later wide identities, excess empty space, peer misalignment, detached glyphs, wrong arrow endpoints, diagonal segments, node crossings, and unnecessary aligned detours. Catalog validation covers fourteen walkthroughs and all 67 beats. Fresh rendered coverage and final production verification are recorded in the release note after completion.

The corrective release is now live at commit `1850878`: 219 passing tests, 268 independently inspected state captures and 212 adjacent-state pairs, plus owner-authenticated verification of all 100 live lessons and 203 figures without KaTeX errors. The live product-font grouping audit also passes. See [the release evidence and independent storage recovery](subjects-release-2026-10-01.md#corrective-release-verified-live). The implementation fixes this Subjects generation/publication path; it does not claim to migrate stored paper diagrams or prove future generated content without fresh review.
